4. PERFORMANCE (measured in the shipped browser build, Intel HD Graphics 5500, 960x540)
----------------------------------------------------------------------------------------------
Numbers come from a throwaway Playwright probe that wrapped renderer.render, counted frames and read
renderer.info — the probe was deleted after use, the measurements are kept here.

  before this pass                              after
  --------------------------------------------  -----------------------------------------------
  ~10.0 ms/frame of JS per frame                ~6.3 ms worst case (16 cars, night, rain)
  8 requestAnimationFrame loops every frame     8 loops, the UI one throttled to ~30 Hz
  12.1k triangles, 152 draw calls, 9.5 ms        88-121 draw calls, 4.3-8.2 ms render
  drawing buffer reallocated 9x in 4 s          governor changes one 0.05 step/s with a cooldown
  44.9 FPS @ pixel ratio 0.7 (worst case)       57.4 FPS @ pixel ratio 1.0 (worst case)

What was actually wrong and what changed:
- MSAA was the single biggest cost on this GPU (9.49 -> 5.21 ms with it off). It is now off on weak
  adapters (probed via WEBGL_debug_renderer_info) and on Low/Medium quality.
- MeshStandardMaterial -> MeshLambertMaterial for road, ground, kerbs, lines, props and trees.
- Each car GLB was 20+ draw calls; models.js now flattens it to one mesh per material at load time.
- Screen blinking: the dynamic-resolution governor called renderer.setPixelRatio() every 0.5 s with a
  new value, which reallocates the WebGL drawing buffer and flashes. It now moves at most one 0.05
  step per second, honours a cooldown, remembers a ceiling and no-ops when the value is unchanged.
- Night races used a SpotLight for the headlights (the most expensive light type); replaced with an
  additive cone. Rain went 1800 -> 800 segments. HUD writes go through a compare-and-set cache.
- Two frames-per-second bugs fixed along the way: features.js and extras.js both rewrote #gear/#spd
  every frame, fighting the main loop (visible flicker).

Gameplay / presentation added in the same pass:
- Six distinct locations: per-location surface colour, kerbs (alternating vertex-coloured ribbons),
  shoulders, guardrails, scenery (grandstands, cacti+rocks, pines+snow, neon pylons, palms, oil drums,
  warehouses + smoke stacks) and a per-location sky/fog tint. Verified by reading the live material
  colours per location and by screenshots of all six.
- Per-car engine sound: every car index owns a two-oscillator voice with its own pitch, waveform and
  filter, plus the two nearest rivals mixed in with distance falloff. Voices are stopped when the
  race ends so nothing drones or accumulates in the mixer.
- Fixed a first-run crash found by the headless suite: boot() read save.set.aa before extras.js had
  created save.set, so a brand-new player (empty localStorage) would have thrown while loading.
- The horned AI now swerves .9 of full lock instead of .7: the reaction is visible and the acceptance
  assertion no longer sits exactly on its threshold (the horn scenario was failing ~1 run in 10).

5. WHAT IS STILL UNVERIFIED (honest)
----------------------------------------------------------------------------------------------
- No physical gamepad, phone or tablet was available. Controller tests use the real Gamepad API path but
  with a stubbed pad object in Chromium; gyro tests use synthetic DeviceOrientationEvent. Real-device
  differences that are NOT verified here: DualSense trigger axes, some Android pads that lie about
  mapping/button counts, iOS Safari motion-permission prompt, iOS/Android fullscreen + orientation lock,
  Screen Wake Lock, PWA install prompt, and whether haptics physically feel right (we assert that
  vibrationActuator.playEffect is called with sane magnitudes, not the rumble itself).
- The on-screen wheel, gyro and layout editor were exercised with pointer events at phone size, not on a
  real touchscreen (multi-touch simultaneity is simulated, not physically tested).
- Online: the horn/taunt relay is rate-limited server-side (220 ms horn, 3 s taunt) but the server was not
  run against real clients in this pass.
- Not implemented yet (tracked, not claimed): living track, touge duels, driver-DNA coach, telemetry,
  nitro-skill scoring, crews/economy expansion, photo mode, livery/tuning/track editors, weather/surface
  extension, real multiplayer matchmaking/spectate/anti-cheat, wheel force feedback, WebXR, multi-monitor,
  localisation. Anything shown in menus but not implemented is labelled "coming soon".
